# Generation four - the machine-written workshop

> Written from this system's own measured record — its README tables, the task

## 1. Hypothesis

A loop with no tools can write, measure and rewrite a strategy until one attempt beats the best sealed result on record.

## 2. What it is

strategy.py is GENERATED by a seat that cannot write files; it returns Python as a string and the sandbox parses it before anything imports it.

**Data consumed:**

- 5m candles, five USDT majors, via the shared catalogue
- the intraday harness's cached indicator panels

## 3. What helped

- **Volatility-scaled entry bar (asset's own measured daily volatility instead of a fixed 3% opening range)** — the sealed-window collapse is gone: 65 trades in 2026 against the incumbent's 24, and 27/68/74/96/103/96/116/111/91 per year - stable through bull AND bear, which is what a regime-neutral bar should do *(ede2570)*
- **The forensic refusal count that produced the diagnosis** — the fixed 3% bar was refused 319,662 times in 2026 and the trend filter only ten - which is how a fixed percentage was identified as a different rule in every volatility regime *(ede2570)*
- **A sandbox that PARSES generated code before anything imports it** — the only reason an unattended seat is allowed to author strategy.py at all; code that could reach the filesystem or the network is refused rather than sandboxed *(30c71db)*

## 4. What hurt

*This section matters more than the one above: it is the part that cannot be
reconstructed from the code.*

- **Trading more often** — +495.35% training at 20.91% drawdown - the best this laboratory has ever measured - produced -5.81% sealed 2026. Gross was -0.87%; the toll on 65 round trips was 4.9% *(ede2570)*
- **The frequency diagnosis itself** — correct and useless. The bar WAS regime-dependent, fixing it restored the trade count, and firing twenty times more often paid the toll twenty times more often rather than manufacturing an edge *(ede2570)*
- **An overnight loop nobody was measuring** — 173 attempts across nine hours produced exactly one training result and never opened 2026, while the watchdog reported 'ok' every thirty minutes throughout *(53f0664)*
- **EXHAUSTED_MARKERS missing the phrase 'session limit'** — 116 of those 173 attempts were spent asking a subscription that had already refused, once a minute, against two reset windows *(53f0664)*
- **A gate keyed on FunctionDef and ClassDef only** — 17 attempts refused for CORRECT code - ast.Lambda is neither, so every `key=lambda item: ...` reported that `item` was not available *(53f0664)*

## 5. What is still open

- **Whether a machine-written strategy can beat a hand-written one at all** — the generation-four loop never produced a candidate that reached a sealed reading, so the question was abandoned rather than answered

## 6. Rules learned

1. Making a configuration trade MORE often pays the toll more often; it does not manufacture an edge. Anyone proposing to rescue a configuration by raising its frequency owes an answer to generation four.
2. +495% training producing a forward loss is the strongest anti-prediction datum on record here: training return does not rank forward return.
3. A gate that refuses CORRECT code fails silently and is as bad as one that permits bad code - the author is told a rule it is breaking, the rule does not exist, and it cannot comply.
4. A watchdog that reports 'ok' while nothing is achieved is not a watchdog. Liveness is not progress, and only progress is worth alerting on.
